# MCP Server（工具扩展）

MCP Server 通过 [Model Context Protocol](https://modelcontextprotocol.io) 为 Agent 提供工具能力。挂载到 Agent 后，Agent 在运行时即可调用这些工具——这是「扩展靠组合」的关键：**需要调用外部系统/工具时用 MCP，而不是把逻辑硬编码进平台**。

## 三种传输类型

一个 MCP Server 有三种连接（传输）方式：

| 类型 | 关键字段 | 说明 |
|------|---------|------|
| **stdio** | `command`、`args`、`cwd`、`env` | 以子进程方式启动的本地 MCP Server（需在执行机可用） |
| **sse** | `url`、`headers` | 远程 Server，Server-Sent Events |
| **http** | `url`、`headers` | 远程 Server，Streamable HTTP |

> [!NOTE]
> **Group 不是一种传输类型，而是更高一层的「聚合」概念** —— 它把多个已有 MCP Server 组合成一个代理。因此它在「MCP」页面有**独立入口**，详见下文《Group（多后端聚合）》。

## 创建与挂载

「MCP」页面右上角有两个入口，都以弹窗（Modal）方式打开，填完即时创建，无需跳转独立页面：

1. **添加 MCP** —— 新建单个 MCP Server：选传输类型（stdio / SSE / HTTP）并填连接配置（stdio 填命令/参数/工作目录；sse/http 填 URL 与请求头）。
2. **添加 Group** —— 新建一个聚合代理（见下文）。

保存后，在 Agent 配置中挂载该 MCP Server。列表里点击任意卡片即可再次打开弹窗编辑；卡片右上角的「更多」菜单可克隆或删除。

## 探测工具列表

- 创建/编辑时用 **探测工具（probe-tools）** 临时连接，预览它暴露的工具，确认无误再保存。
- MCP Server 详情页的 **工具列表** 展示当前可用的全部工具。

## 内网 MCP 地址

由平台自身发起的远程 MCP 连接会逐跳校验重定向和 DNS 结果，并把连接固定到已校验的地址。公网地址无需额外配置。若要访问企业内网服务，请把它的精确 DNS 主机名加入 `TRUSTED_MCP_HOSTS`（逗号分隔）并重启 API。配置项不接受协议、端口、路径、通配符或 IP 字面量；回环及其他保留地址始终禁止，云元数据端点 `169.254.169.254`、`100.100.100.200`、`fd00:ec2::254` 及其映射表示即使命中精确白名单也会硬拒绝。

从允许私网 IP 或私网 DNS 的旧版本升级时，请先为服务分配稳定 DNS 主机名，并只把这个精确主机名加入 `TRUSTED_MCP_HOSTS`。工具探测与 Group 内联 HTTP/SSE 后端都会使用受保护的传输。若远程 MCP 配置被直接导出给底层第三方 Agent CLI，最终连接由该 CLI 自行建立；a2wave 无法在外部可执行程序内部强制网络策略，因此还应对 Agent 运行环境配置出站网络限制。

Group 后端凭证会按每次真实执行尝试独立解析。a2wave 只在 worker 启动前为每个 Group 创建一个不可预测的私有载体；Group 代理读入后立即删除，worker 在成功、失败、取消、超时或启动失败时都会幂等清理。诊断和配置预览不会产生这些文件，并发的管理员与普通用户运行也不会共享载体。

## Group（多后端聚合）

通过「MCP」页面的 **添加 Group** 入口创建。Group 把多个后端 MCP Server 聚合在一起，通过代理做 **渐进式披露**：列举工具时只返回精简信息，Agent 真正需要某个后端时再展开其完整工具定义，从而降低上下文开销、提升大型工具集下的可用性。

Group 内部按「分组键 → 后端列表」组织，每个后端二选一：

- **内联（inline）**：在弹窗里直接定义一个 stdio/sse/http 后端（含名称、连接字段）。
- **引用（ref）**：从下拉选择器里挑一个已存在的 MCP Server 复用。

约束：分组键与内联后端 `name` 仅允许字母/数字/`-`/`_`（**不能含 `:`**，因为工具名用 `后端名:工具名` 格式）；每组 1–20 个后端，内联名在组内唯一。

## 使用范围（谁能挂载）

每个 MCP Server 有一个 **使用范围**，决定谁能把它挂载到自己的 Agent：

| 范围 | 含义 |
|------|------|
| **仅自己** | 只有属主本人的 Agent 能挂载（普通用户新建 sse/http 的默认） |
| **仅管理员** | 只有管理员的 Agent 能挂载（stdio 强制此值） |
| **所有用户** | 显式共享给全体，任何登录用户都能挂载（**只有管理员能设置**） |

规则：

- **stdio 类型（含内联 stdio 的 group）会在执行机上运行本地命令**，等同宿主命令执行，因此**只能由管理员创建，且强制「仅管理员」，无法放宽**。
- **sse / http（纯 URL 远程）默认「仅自己」** —— 它的 URL、请求头、环境变量属于你的私有凭证，不会被隐式分享出去；你自己随时可挂载。
- **共享是管理员的显式动作**：只有管理员能把某个非 stdio Server 设为「所有用户」，让全体用户挂载（管理员在 MCP 编辑页的「使用范围」下拉里操作，该下拉仅管理员可见）。共享状态是持久化的，与属主之后被升/降级无关。

运行时，普通 stdio 和其他「仅管理员」MCP 是**管理员所拥有 Agent 的已授权能力**。只要 Agent 属主仍是启用状态的管理员，这些已挂载能力就可用于 Web Chat 调试、直接 Run、评测，以及 Gateway API、OAuth、A2A、飞书/Slack/Discord 等原生聊天渠道和定时触发；Group 的内联与引用后端遵循相同规则。每次真正开始执行时都会重新检查属主状态，因此属主被降级、停用或删除后权限立即失效。

系统内置的 `a2wave-platform-admin` 是例外：它属于后台控制面，只允许当前仍为启用状态的后台管理员通过 Web Chat 调试、直接 Run 或评测使用。Gateway API、OAuth、A2A、原生聊天渠道、Chat Page 和定时触发都不会获得该能力，即使 Agent 属主是管理员也不例外。

> [!NOTE]
> 你只能挂载**自己拥有的**、或被管理员设为「所有用户」的 MCP Server。别人「仅自己」的 Server（即使是 sse/http）不会出现在你的选择器里，也不能被绑定；即使是被共享的 Server，你在列表/详情里看到的凭证字段也会被**打码隐藏**（挂载与运行由服务端按 id 解析，不需要你拿到明文）。

此外，平台还有内置、对普通用户隐藏的 MCP（如内部路由），列表与选择器会自动过滤。

## 排错

| 症状 | 可能原因 | 解决 |
|------|---------|------|
| 探测不到工具 | 命令/URL 错误、依赖缺失 | 检查 command/args 或远程可达性 |
| stdio 启动失败 | 执行机缺少对应命令 | 在执行机安装依赖，或改用 http/sse |
| 工具名冲突 | group 内 inline 名重复或含 `:` | 改名，保证组内唯一且不含 `:` |
| 普通用户看不到 / 挂载不了某 MCP | 使用范围为「仅管理员」、别人的「仅自己」、或为内置隐藏项 | 请管理员把它设为「所有用户」共享，或改用你自己创建的 sse/http Server |
| 想把自己建的 MCP 共享给同事 | 「所有用户」只能由管理员设置 | 请管理员在 MCP 编辑页把它改为「所有用户」 |
