# 长期记忆（Memory）

长期记忆让 Agent 在跨会话任务中复用稳定知识，又不必在每次 Run 中加载全部历史。记忆归属于 **Agent**，而不是某个请求者：有权调用同一个 Agent 的人可能共享并受益于同一份记忆。

> [!WARNING]
> 不要在 Agent 记忆中存放请求者私密信息，也不要把它当作个人档案。敏感知识应使用共享边界合适的 Agent。

## 渐进式披露

记忆分为三层：

1. **启动摘要与目录 — `MEMORY.md`**：包含紧凑的 Agent Summary、由服务器确定性生成的活跃主题目录，以及固定披露指引。开启上下文注入后，Run 启动时只注入这个紧凑文件。
2. **有边界的主题 — `memory/topics/*.md`**：按稳定复用范围组织详细长期知识，例如某个仓库的交付流程或某项集成契约。Agent 发起一次聚焦回想，由服务器只选择并返回最相关的一个活跃主题；只有无匹配或出现具体跨主题依赖时才继续读取。不活跃主题移入 `memory/topics/archive/`。
3. **历史记录 — 每日与每周日志**：`memory/YYYY-MM-DD.md` 保存 Run 摘要，旧日志可整合到 `memory/weekly/*.md`。当主题不匹配、内容不足或需要准确时间线证据时，Agent 才搜索历史。

内置 `a2wave-memory` Skill 会引导 Agent 按“启动目录 → 单次主题回想 → 必要时搜索历史”逐步披露。运行时主题读取有硬预算，Agent 不能在一个 Run 步骤中批量加载全部主题。当用户把回答限定为已保存主题并要求不要猜测时，无匹配会立即停止，不再进入历史搜索。

## 自动维护方式

- **Run 启动时**：服务器在注入前校验并确定性重建 `MEMORY.md` 目录，主题正文不会被复制进启动文件。
- **Run 结束后**：平台在后台生成每日日志并提取结构化长期洞察，不阻塞本次回复；记忆 Tab 会在有限的后台完成窗口内自动补刷。每个入队任务只冻结刚完成的当前对话轮次，因此旧轮次的拒绝写入不会抑制后续轮次，后来的消息也不会泄漏进较早摘要。匹配的洞察更新已有稳定主题；即使只有一个可复用条目，只要它与某个已有主题存在唯一且多维的明确关联，也会直接补充该主题。但只共享一个产品名、仓库名等实体词，或只使用这种粗粒度实体 scope，不会把不同复用范围合并；自动新建主题仍至少需要两个可复用条目，证据不足或归属不明确的候选保留在 Run 或工作日志历史中。写入已有主题前，服务器会保守折叠新增及既有的、仅有格式差异或少量等价措辞的重复事实；对象、取值、条件或顺序不同的事实继续分别保留。已有自定义洞察提示词继续决定什么内容值得提取，平台会追加 Topic V2 结构化输出契约；不符合契约的输出只保留在历史层，不猜测其主题边界。用户说明当前轮次是临时内容或不要长期保存时，后台工作日志和洞察都会跳过，Run 与审计记录仍保留。
- **用户明确要求记忆时**：新增一条记忆只发起一次限定范围的 remember 请求，由服务器原子完成主题选择、去重、写入和目录更新；成功响应就是持久化确认，不再重复读取核验。只有更新或遗忘已有内容时才读取精确主题并执行 replace。“明确”指要求记忆系统执行记住、保存、添加到记忆主题、更新或遗忘的祈使请求；仅说明某事实“长期、稳定、固定”，或要求“只需确认理解”，不会授权当前对话直接写入，普通稳定陈述可由 Run 后自动洞察按长期性门槛处理。明确说不要保存会同时禁止直接与后台记忆持久化。显式交互式变更也会跳过 Run 后工作日志和洞察，因此同步响应是唯一的持久化结果。运行时会按原始用户请求签发最小写权限。主题 ID、路径、frontmatter 与主目录均由服务器管理。
- **每日到每周日志整合**继续保留，并与主题维护相互独立。

## 主题边界与重组

| 对象 | 边界 | 到达边界后的行为 |
|------|------|------|
| Agent Summary | 估算 500 tokens | 拒绝新的摘要条目；绝不调用模型压缩整个文件 |
| 主题目录 | 估算 700 tokens | 条件允许时归档最早更新且未受保护的主题 |
| 完整 `MEMORY.md` | 估算 1,400 tokens | 拒绝非确定性或超限重建 |
| 单主题软限制 | 估算 1,500 tokens | 标记“建议重组” |
| 单主题硬限制 | 估算 2,000 tokens | 不提升候选；来源继续保留在 Run / 工作日志历史中 |
| 活跃主题 | 16 个且合计 64 KiB | 新增前归档较早且未受保护的主题 |
| 每个 Agent 总记忆 | 10 MB | 拒绝写入 |
| 每日日志 | 200 个文件 | 超出后移除最旧每日日志 |

V1 明确**不自动对主题文件做语义压缩**。达到软限制只显示警告；达到硬限制就停止提升，避免静默删除或改写长期知识。编辑者可以归档、恢复、合并主题，也可通过高级 API 在完整原文块覆盖校验下拆分主题。自动语义压缩主题属于未来独立能力，需要另行设计与审批。

## 旧版 `MEMORY.md` 迁移

如果已有 Agent 的主文件没有受管主题目录，它会继续处于 `legacy_single_file` 模式，不会被隐式转换。

编辑者可在记忆 Tab 中分两步迁移：

1. **预览主题化**：记忆模型只负责按稳定复用范围对源块分组。每个源块必须原文复制到且仅复制到一个拟议主题，覆盖校验通过后才显示预览。
2. **提交主题化**：再次确认源文件未变化，在 Agent 索引目录之外保存回滚备份，然后写入主题文件、确定性目录并重建索引。任一步失败都会恢复原文件。

显式迁移完成前，旧模式继续保留原单文件兼容行为，包括旧的主文件压缩路径；Topic V2 不再使用这个压缩路径。

## 记忆 Tab 配置

| 配置 | 取值 | 默认 | 说明 |
|------|------|------|------|
| `memoryEnabled` | 开/关 | 关 | 总开关；开启后挂载内置 Skill |
| `memoryContextMode` | `off` / `memory` | `memory` | 注入紧凑启动摘要与主题目录 |
| `memoryRecallLevel` | `weak` / `medium` / `strong` | `medium` | Agent 启动渐进回想的积极程度 |
| `memoryWorklogEnabled` | 开/关 | 开 | Run 结束后写入每日日志 |
| `memoryAutoInsight` | 开/关 | 开 | 将 Run 后长期洞察路由到有边界主题 |
| `memoryConsolidationEnabled` | 开/关 | 开 | 把旧每日日志整合为每周历史 |
| `memoryModel` | 模型名 | 继承 Agent | 用于工作日志、洞察路由、旧版迁移预览与日志整合 |

“主题记忆”区上方以卡片网格展示元数据，不预加载正文；选择一个活跃主题后，下方整宽阅读区才会精确读取并按 Markdown 排版展示正文。编辑者可归档、恢复主题并预览旧版迁移。原始文件浏览器仍用于检查和兼容管理，但受管主题元数据和主目录归服务器所有。

## 搜索与向量嵌入

默认支持关键词搜索。配置 `embeddingEnabled`、`embeddingBaseUrl` 与 Embedding API Key 后可启用语义搜索。结果按活跃主题、已归档主题、每周摘要、每日日志、主启动目录的顺序分层排序，并折叠重复片段。

## 部署提醒

记忆文件与索引存放在本地 `./data`。容器部署必须把它挂为持久卷：

```yaml
volumes:
  - a2wave-data:/app/data   # a2wave.db + 记忆文件 + 搜索索引
```

## 排错

| 症状 | 可能原因 | 解决 |
|------|---------|------|
| Agent 不记事 | 未开启 `memoryEnabled` | 在 Agent 上开启记忆 |
| 没有创建新主题 | 自动候选只有一个条目，或已触及硬限制 | 查看 Run / 工作日志历史；对单个高价值条目明确要求记忆，或先重组主题 |
| 主题显示警告 | 已超过 1,500-token 软限制 | 在达到 2,000 tokens 前重组、选择性合并或归档过时知识 |
| 重启后记忆丢失 | `./data` 未持久化 | 挂载持久卷 |
| 无法使用语义搜索 | 嵌入配置不完整 | 配齐 enabled + Base URL + API Key |
| 无法执行旧版主题化 | 当前用户只有 viewer 权限，或已是 Topic V2 | 使用 owner/editor 账号，或直接管理已有主题 |
